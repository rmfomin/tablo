# Настройки в JSON-бэкапе

## Поведение

- Полный экспорт из меню и напоминания включает `settings: { version: 1, values: { ... } }` рядом с `spaces`. Версия основного формата остаётся `3`.
- Экспорт отдельного пространства не включает глобальные настройки. Его импорт также не меняет их, даже если файл содержит дополнительные поля.
- В бэкап входят тема, сворачивание боковой панели, открытие ссылок, подсветка, отображение поиска и групп, включение напоминаний и интервал в днях.
- Время последнего экспорта, отложенное напоминание, старт таймера, выделение, открытые окна и другие временные состояния не переносятся.
- При импорте применяются только присутствующие поля с допустимыми значениями. Отсутствующие и некорректные поля сохраняют текущие настройки; при первом запуске действуют значения по умолчанию.
- Старые бэкапы без `settings` восстанавливают закладки и сохраняют текущие настройки.
- Неизвестные поля игнорируются. Некорректный блок или неизвестная версия настроек пропускается целиком, сохраняя возможность восстановления закладок.
- Для новых напоминаний на чистой установке отсчёт начинается при восстановлении настройки включения.

## Единая схема и расширение

Выбран отдельный блок с версией и единая схема `src/newtab/05-entities/preferences/model/preferences.ts`. Копирование всего Zustand store исключено: оно смешивает настройки, служебное состояние и команды. Отдельные списки для экспорта и storage создавали бы риск пропустить новое поле.

Для добавления настройки:

1. Добавить поле в `UiPreferences` и определение в `preferenceDefinitions`.
2. Задать валидатор, значение по умолчанию и `includeInBackup`. Для экспортируемых полей значение по умолчанию обязательно.
3. Чтение и запись Chrome Storage, поиск изменений, начальные значения и JSON-бэкап используют эту схему автоматически. TypeScript требует определение для каждого поля `UiPreferences`.
4. При добавлении независимых необязательных полей сохранить `settings.version = 1`: старые версии приложения их проигнорируют, новые прочитают старые файлы.
5. При несовместимом изменении типа или смысла поля добавить миграцию и новую версию настроек. Не переиспользовать прежнее имя с другим смыслом в версии `1`.

Данные JSON не передаются напрямую в store: нормализатор перебирает только собственные известные ключи и проверяет значения. Неподдерживаемая версия основного формата бэкапа отклоняется до замены данных.

## Проверка

Проверить diff и оба пути полного экспорта, импорт старого файла, частичных настроек, неизвестных полей и неизвестной версии. Сборку, проверку типов и тесты запускать только по отдельной просьбе пользователя согласно локальным инструкциям. Существующие проверки структуры закладок адаптированы к дополнительному блоку настроек без добавления новых тестов.
